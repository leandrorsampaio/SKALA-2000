Claude Code Telemetry

Every reading the panel can pull from Claude Code — what is wired up today, what is sitting there unused, and what simply is not available. Each row names the value, its type, and the instrument it suits.

Nothing here is a published API except claude agents --json. The rest is read from files Claude Code writes for its own use, so every reading is defensive: a changed field costs one signal, never the panel.

G Events, pushed by hooks

Some things leave no trace on disk: “that just finished” and “this is waiting for you” are moments, not states. Hooks curl them into POST /v1/signals/{id}. Every one carries a TTL, so a source that stops reporting stops lighting its lamp.4

Notes

  1. Only status: "busy" has actually been observed. What an idle session reports is unconfirmed, which matters for any rule that fires on stopped working. The safe design leans on the Stop hook for the transition and the session list for presence, so it holds either way.
  2. lastPrompt and detail are verbatim text you typed or Claude wrote. Fine on your own screen; think twice before putting either on a panel that floats over a shared display.
  3. The assistant record says claude-opus-5; only cost-state says claude-opus-5[1m]. Sizing the window off the assistant record reads 200K when it is really 1M — an 80% full gauge that should say 20%.
  4. The four wired hooks ship in scripts/install-claude-hooks.sh and the endpoint they call is tested, but the hooks are not installed here yet, so none has been observed firing end to end.
  5. stats-cache.json is only rewritten when you run /stats. The copy on this machine is five months old. Not a live source.
